# PARSE-ENV-013 expired historical signer acceptance

Status: implementation independently reviewed and accepted. Focused/full
core/workspace tests, targeted Duvet queries/full trace, formatting, strict
Clippy, and full local `cargo xtask ci` pass at exact-source receipt SHA-256
`f97939d0ca0c7c95aeb415f19934018c5c4c7c9fa2859eca5351b856ba9c0d26`
(Verus 2,047/3,183/1,371, zero errors). The narrow native-attendance gate is
enabled. Hosted Linux/Pages checks remain pending.

## Goal and scope

Verify that an otherwise authorized historical signed backup remains readable
after the signing certificate's recorded key-expiry time has passed. The
existing [PARSE-ENV-013](parsing-requirements.md#parse-env-013) acceptance
checks that expiry observations are exposed without making a current-validity
claim, but its official signed fixture has no expiry metadata. This slice adds
one locally generated, official-producer positive fixture with an expired
signer and exercises it through the public reader.

The result is offline fingerprint-authorization evidence only. The test MUST
not add or imply a project rule for current certificate validity, revocation,
or Web-of-Trust status, and makes no Verus claim about cryptography or reader
control flow.

## Fixture requirements

1. A checked-in fixture MUST be generated by official Duplicity 3.0.7 and the
   pinned GnuPG version from a deterministic source tree. Its v4 signing
   certificate MUST include a finite key-expiration duration. The fixture
   generator MUST pin a reproducible producer/signing clock such that the
   manifest and required volume signatures were created before the calculated
   key-expiry instant. It MUST record all tool versions, normalized producer
   commands, test-only credential source, key creation time, expiration
   duration, calculated absolute expiry, signature creation times, output
   object names, sizes, and SHA-256 hashes. Any wrapper used to supply the
   GnuPG clock MUST be checked in and hashed as part of provenance.
2. The fixture MUST be generated at a fixed historical timestamp whose
   signing-key expiry is earlier than the test's execution time. The focused
   test MUST explicitly compare the fixture's calculated expiry instant with
   the test process's current UTC time and fail with a clear precondition
   message if that clock condition is false. The reader itself receives no
   clock input and MUST NOT use this test-side comparison to decide whether to
   accept the signature.
3. Independent producer inspection MUST establish that the manifest and
   required data volume each carry a valid signature made before expiry by the
   expiring primary key itself. The fixture MUST NOT use a signing subkey.
   Provenance MUST identify the exact signer component for each document
   signature and establish that it is the permitted primary fingerprint.
   Provenance MUST derive the primary key's expiry from that primary key's
   self-signature metadata and creation timestamp; it MUST not confuse the
   expiry duration with an absolute timestamp or infer which component a
   flattened metadata-pool record describes. The fixture MUST have no
   revocation used to explain its result.
4. Use one completed Full set with one required data volume and one selected
   snapshot date. The source-content oracle MUST record raw component paths,
   entry kinds, modes, file/directory timestamps, file lengths and SHA-256
   hashes, plus symlink targets where present. Honor only exclusions already
   recorded for official comparison, including the documented symlink-mtime
   exclusion.
5. The test MUST use checked-in public test credentials and MUST NOT invoke
   Duplicity, GnuPG, network key lookup, or other crypto executables at runtime.
   Live S3 access is not required.

## Normative acceptance requirements

### 1. Historical signature positive control

The public reader MUST read the checked-in Full manifest and required volume
with the fixture's caller-supplied secret export/passphrase, signer export,
exact permitted primary fingerprint, and `require_signature = true`. The
message-password list MUST be empty for the public-key-encrypted profile. The
same immutable context MUST apply to both required objects.

After the test establishes that current UTC time is later than the provenance-
calculated key-expiry instant, `Catalog::read_snapshot_with_crypto` MUST
successfully return the selected Full snapshot matching the independent
source oracle despite the recorded expiry being in the past. The ordered open
log MUST contain exactly the manifest followed by Full volume 1.

### 2. Expiry evidence without a validity decision

The successful result MUST contain exactly two `OpenPgpAuthorized` evidence
records, one for the manifest and one for the data volume. Each MUST report the
exact permitted primary fingerprint. The certificate metadata pool MUST
retain the fixture certificate's exact primary fingerprint, creation time,
and key-expiration duration. The test MUST calculate the absolute expiry from
the recorded key creation time and duration and confirm that this instant is
earlier than the process time at test execution.
   Fixture provenance MUST establish that this retained duration is the
   primary key's self-signature value; the pool value alone does not identify
   which certificate component it describes.

The evidence API MUST continue to expose expiry as an observation. The test
MUST NOT label the certificate currently valid, reject it based on current
time, infer revocation status, or claim Web-of-Trust validation. Credential
bytes and passphrases MUST NOT appear in output, diagnostics, evidence, or the
snapshot.

## Requirement and assurance mapping

The focused test MUST link to PARSE-ENV-013 for historical offline
fingerprint-authorization scope, PARSE-ENV-012 for complete primary-fingerprint
authorization, PARSE-ENV-019 for applying unchanged signer policy to each
required object, PARSE-ENV-021 for credential non-disclosure, and PARSE-ENV-023
for the authorized-result and certificate-metadata observations. These links
do not prove cryptographic primitives or a present-day certificate-validity
policy.

Register the test in the existing OpenPGP reader edge-test ledger. To enforce
the Duvet trace without claiming a Verus crypto proof, add a narrow native
milestone such as `openpgp-expired-historical-signer`, with this exact test and
the public reader composition implementation. It MUST set
`proof_required = false` and state that it enforces native Duvet/test
attendance only. Enable the gate only after independent implementation review
accepts the fixture provenance, reader result, and requirement mapping.

## Exclusions

This acceptance does not test revoked certificates, current-expiry rejection
policy, online status or key retrieval, Web-of-Trust, multiple certificates,
signing-subkey behavior or expiry, alternative hashes/ciphers, arbitrary
historical profiles, crypto primitives, side-channel behavior, filesystem
publication, live S3, or complete reader/controller refinement. The fixture
uses the already-supported v4 RSA-2048 profile only for this expired-key
observation; this acceptance makes no broader RSA compatibility or
cryptographic claim.
